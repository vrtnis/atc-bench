Scores

Two skills · keeping the facts and auditing them

Six of the eight models answer more than 90% of the factual questions. The audit spreads those six from 43% to 85%.

The factual questions ask what was said and where the aircraft are, such as an aircraft's last cleared altitude. The audit asks the model to match those facts to a rule. Claude Opus 5.5 gets 93% of the facts and 56% on the audit.

Background

Air traffic controllers talk about "keeping the picture". It means following a lot of aircraft at once, remembering what each one was told, and noticing when what an aircraft is doing stops matching that.

A lot of the work people want from AI agents has the same shape: watching a long, busy stream and checking it against written rules. Air traffic control is a good place to test it, because the rules are public. FAA Order JO 7110.65, the air traffic control handbook, sets out what is required, so every answer can be checked against the text.

Each task is one scripted transcript of six or seven busy minutes at a made-up US airport, with 16 or 17 aircraft, three radio frequencies, the phone line between the controllers, and radar positions every five seconds. The model reads it one minute at a time and starts each minute with no memory of the last one.

notes.md · all the model carries forward

All the model keeps between minutes is a small notes file, about two pages for a sixteen-page transcript. The notes file is there because controllers work from written notes too. Paragraph 2-3-1 of the order has them post current traffic and clearances on flight progress strips and "maintain only necessary current data".

After the last minute the transcript is taken away, and the model sees the questions for the first time. The main one is an audit: list every instance where a requirement of the order was not met. The model is the auditor and never directs traffic itself.

Methodology

What the model does, and how it is scored

Each transcript has six to ten scripted failures and four to ten look-alikes. A finding counts for a failure when it names the right position (tower, ground or approach) and one of the aircraft involved. A judge model, Claude Opus 5.5, then grades the written reason against two to four criteria for that failure, and the essential ones must be met.

Audit accuracy is the share of failures found with every essential criterion met, multiplied by the share of look-alikes left alone, averaged over the transcripts. Reporting something that isn't scripted neither helps nor hurts.

01 · Finding
Names the right position and one of the aircraft involved.
02 · Reason
Graded by a judge model against a short list of criteria. The essential ones must be met.
03 · Look-alikes
Count against the model only when a finding is about that event.

Making the benchmark hard to game

  • Look-alikes. A model that flags everything unusual loses credit, because the score is multiplied by the share of look-alikes left alone.
  • A private test set. The six test transcripts, their answer keys and the generator are not published. This page describes only the public sample.
  • A clean start every minute. Each minute is a new conversation. A script cuts the notes to the limit and deletes everything else in the working folder, and files written anywhere else are reported with the score.
  • No public internet. The sandbox can reach the two model providers and nothing else.
  • The questions come last. The model doesn't see them until the transcript is gone, so it can't take notes aimed at them.

How it was run

Every model ran on mini-SWE-agent on Valkyrie, in Modal sandboxes. It works with both Anthropic and OpenAI models, so each one gets the same harness, and it gives the model only a shell. Each minute gets 300 seconds and the answer step gets 420.

Discussion

What the results say

  • The top three are level. Each model ran once, so a gap of less than about ten points is noise.
  • Finding most failures is different from finding all of them. Claude Fable 5.2 passed 39 of 46 failures and flagged no look-alikes. It audited one transcript in six without a miss, because each transcript has about eight failures.
  • Models rarely flag a look-alike. The low scores come from missed failures.
  • Cost varies a lot. The six transcripts cost $2.58 with GPT-6.1 Sol and about $54 with Claude Fable 5.2, for the same score.

Limitations

  • Each model ran once, on 46 failures.
  • No controller has reviewed the answer keys.
  • The traffic is simulated, the airport is made up, and the notes limit is a number chosen for this benchmark.
  • The judge is also one of the models tested. Claude Opus 5.5 graded every model including itself, and it ranked itself fifth.

Conclusion

ATC-Bench measures one specific skill: following a long, busy stretch of activity with only a few notes to lean on, then auditing it against a written rulebook. Other benchmarks test whether a model understands single radio calls, or have the model direct the traffic itself. ATC-Bench adds a different test: auditing a whole stretch of traffic from the model's own notes.

For aviation, it is a first measure of whether models could help with safety review against the FAA handbook. Going by these results, the answer today is "not without a person checking".

The same kind of work shows up well outside aviation too. Compliance monitoring, call quality review and control rooms all come down to watching a lot happen and checking it against the rules.
